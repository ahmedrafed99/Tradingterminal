Problem. 1,141 style={{}} objects encode design tokens (var(--color-*), RADIUS.*) that already exist as CSS variables — and split hover state across onMouseEnter/onMouseLeave handlers instead of CSS :hover.

Solution. Extract structural patterns into Tailwind utility classes and a thin CSS layer; replace onMouseEnter/Leave handlers with :hover rules; keep style={{}} only for dynamic runtime values (drag position, computed widths).

  • → locality: token changes land in CSS, not scattered across 78 files
  • → leverage: removing onMouseEnter/Leave from every button shrinks call-site complexity
  • → interface: component props stay the same — pure implementation change

After — one deep module

Button.tsx variant · tone · size

toolbar variant → pill sizing + bg token

Problem. Button.tsx is the only real module; four shadow button modules duplicate its padding, border, hover, and transition logic without routing through it.

Solution. Add variant="toolbar" | "tab" | "menu" to Button.tsx; delete ToolbarPillButton, DropdownButton, and TabButton; absorb MenuItem's layout into a menu variant.

  • → locality: button hover/focus behaviour lives in one module
  • → leverage: one fix to Button.tsx reaches all variants
  • → interface shrinks: callers drop to variant instead of importing a different file

Problem. Modal.tsx provides only a backdrop; every caller rebuilds the title bar and close button independently, scattering that chrome across 5+ modules.

Solution. Add optional title and actions props to Modal.tsx; callers that need custom tab bars can still override via children, but the common case becomes one prop.

  • → locality: close-button styling and Escape handling already in Modal — header joins them
  • → leverage: changing modal header design touches one module, not 5
  • → backwards-compatible: existing callers still work if title is omitted

Problem. Checkboxes, toggles, and number inputs are built inline inside each settings modal with duplicated style logic — there are no shared form primitives in components/shared/.

Solution. Extract Checkbox, Toggle, and NumberInput into shared/ using the token system; delete inline implementations.

  • → locality: checked/active visual state defined once
  • → leverage: consistent keyboard/accessibility behaviour across all forms for free
  • → interface: value + onChange — callers stop caring about active-state colours

Unify the icon system — eliminate inlined SVGs

Speculative local-substitutable
frontend/src/components/shared/Popover.tsx ← inline X close svg
frontend/src/components/shared/CustomSelect.tsx ← inline chevron svg
frontend/src/components/shared/MenuItem.tsx ← inline submenu chevron

Current

✕ Popover close: inline 10×10 SVG with hardcoded stroke
✕ CustomSelect chevron: inline 8×5 SVG, non-reusable
✕ MenuItem arrow: inline 12×12 SVG
✓ VerticalSeparator: imports ChevronDown/Up from icons/

Target

✓ All icons imported from components/icons/
✓ Size and colour via props — no hardcoded attributes
✓ Resize: one prop change, not hunting SVG attributes

Problem. Shared icon components exist in components/icons/ but are not consistently used — several shared modules hardcode SVG markup inline, splitting icon maintenance between two approaches.

Solution. Route all inline SVGs through the existing icon system; add any missing icons (X close, select chevron) to components/icons/.

  • → locality: icon sizes and strokes defined once per icon
  • → low risk — mechanical substitution, behaviour unchanged

Top recommendation

Start with the button module

Absorbing the four shadow button modules into Button.tsx is the highest-leverage single change: it deletes duplicated hover/border/transition logic in four files, concentrates all interactive-element behaviour in one module, and the seam already exists — callers just switch to a variant prop. The inline-style sprawl refactor is broader and best done incrementally on top of a stabilised button primitive.
